服务方目录Provider directory

服务方自己登记的 TapeAPI 服务，每天由 tapeapi-doctor 复核一次。每一条都可以用同一条命令自己复核。 TapeAPI services their providers listed themselves, rechecked once a day by tapeapi-doctor. Anyone can recheck any entry with the same command.

只代表通过了 TapeAPI 的自动检查（tapeapi-doctor），不代表推荐、担保或审计；服务质量、价格与合规由服务方自己负责。

A listing only means the service passed TapeAPI's automated checks (tapeapi-doctor), not a recommendation, a guarantee or an audit; each provider answers for its own service quality, prices and compliance.

不排名、不收费、不设推荐位：顺序固定，先按链，再按处理器、#ID。服务方自己提拉取请求登记，我们不替任何人上架，也不代付任何费用。未通过的只标记，不自动删除。 No ranking, no fees, no featured places: the order is fixed, by chain, then processor, then #ID. Providers list themselves with a pull request; we list nobody on anyone's behalf and pay no one's costs. An entry that stops passing is flagged, never removed automatically.

如何上架How to be listed

  1. 让你的服务通过诊断，全部检查通过（退出码 0，允许警告）。AI 服务方指南一步步带你做到这一点。 Make your service pass the doctor: every check passes (exit status 0; warnings allowed). The guide for AI providers takes you there step by step. 
    npx -y --package=https://github.com/BruceLanLan/tapeapi/releases/download/v1.5.0/tapeapi-sdk-1.5.0.tgz tapeapi-doctor <name>
  2. 提一个拉取请求，按名字的顺序在 site/directory/providers.json 里加上你自己的一条（name、added、可选的 contact），并在描述里贴上诊断的最后一行与服务登记表里的确认项。 Open a pull request that adds your own entry to site/directory/providers.json, in the names' order (name, added, an optional contact), and paste the doctor's last line and the confirmations of the service listing form in its description.
  3. CI 只检查格式与顺序，不联网；合并不代表审核了你的服务。每日复核会对你的名字运行诊断，一天之内这里就会显示第一次结果。 CI checks the format and the order only, with no network; merging is not a review of your service. The daily recheck runs the doctor on your name, and its first result shows here within a day.

规则与文件格式见仓库里的 directory/。 The rules and the file format are in directory/ in the repository.

状态的含义What the states mean

ok
最近一次复核，诊断退出码为 0。The doctor exited 0 at the last recheck.
failing
有检查未通过，列出未通过的检查。A check failed; the failed checks are listed.
stale
连续 7 次每日复核未通过。条目仍然保留，由人提拉取请求建议移除。Failing 7 daily rechecks in a row. The entry stays until a person proposes its removal in a pull request.
undecided
读不到链或网络，无法判定；保留前一次的结论，不会因此标为未通过。The chain or the network could not be read; the last verdict stands, and this alone never marks an entry as failing.

复核怎么做How the recheck works

仓库里的定时任务每天运行一次，对每个名字运行 tapeapi-doctor：只读，不用任何密钥，不签名、不发交易。每个名字最多 60 次 JSON-RPC 请求，使用 SDK 默认的公共节点。诊断用一个不可能有效的密钥向每个端点发一次请求，服务方也不花钱。GitHub 可能推迟定时任务。 A scheduled job in the repository runs tapeapi-doctor on every name once a day: read-only, with no key, signing nothing and sending no transaction. It makes at most 60 JSON-RPC requests per name, on the SDK's default public nodes. The doctor sends each endpoint one request with a key that cannot be valid, so it costs providers nothing. GitHub may delay scheduled runs.
