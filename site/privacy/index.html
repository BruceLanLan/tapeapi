我们运营的服务记什么、不记什么What the services we run record, and what they do not

草稿，2026-09-28。本页只说我们自己运营的三样东西：网站 tapeapi.fun、公共服务 api.tapeapi.fun（含 /mcp）、公共中继 relay.tapeapi.fun。下面的日志设置写在仓库的配置文件里，要在这两个 Worker 下次部署后才生效。标"待核实"的地方，我们还没有查到确切答案。Draft, 2026-09-28. This page covers only the three things we run ourselves: the website tapeapi.fun, the public service api.tapeapi.fun (with /mcp) and the public relay relay.tapeapi.fun. The log settings below are in the repository's configuration files and take effect the next time these two Workers are deployed. Where it says "to be verified", we do not yet have a definite answer.

先说结论In short

  • 内容受保护：通道消息端到端加密，中继只见密文；AI 用量回执只带请求与回答的哈希；核验链接默认只带哈希。Content is protected: channel messages are end-to-end encrypted and the relay sees only ciphertext; AI usage receipts carry hashes of the request and the answer; verify links carry hashes by default.
  • 元数据不隐藏：谁在什么时候、从哪个 IP 调用了哪个服务，Cloudflare、公共 RPC 节点和服务方都看得到；写到链上的内容永久公开，包括付款记录。Metadata is not hidden: who called which service, when and from which IP address is visible to Cloudflare, to public RPC nodes and to the service provider; what is written on chain is public for good, payments included.

我们记什么What we record

api.tapeapi.fun

  • 每条 MCP 消息一行日志：消息类型、工具名、调用方标签。调用方标签是 HMAC-SHA256（密钥，IP 与 UTC 日期）的前 12 个十六进制字符：不含 IP 本身，跨天无法关联，没有密钥也无法从标签反推 IP。我们用它统计有多少不同的调用方。One log line per MCP message: the message type, the tool name and a caller tag. The caller tag is the first 12 hex characters of HMAC-SHA256(key, IP and UTC day): it does not contain the IP address, cannot be linked across days, and cannot be turned back into an IP address without the key. We use it to count distinct callers.
  • 限流计数：按 IP 计，放在 Worker 实例的内存里，60 秒一个窗口，不写入任何存储。Rate-limit counters: keyed by IP address, held in the Worker instance's memory in 60-second windows, never written to storage.
  • 内部错误的错误信息。The messages of internal errors.

relay.tapeapi.fun

  • 每个房间是 Cloudflare 的一个 Durable Object，帧只在它的内存里，而且是密文：中继没有解密的密钥。房间空闲 15 分钟（握手房间 10 分钟）后，连同帧一起清除。Each room is a Cloudflare Durable Object; its frames are held in its memory only, and they are ciphertext: the relay has no key to decrypt them. A room idle for 15 minutes (10 for a handshake room) is cleared together with its frames.
  • 每条投递的来源（IP 地址，付费投递则是付款地址）与房间一起留在内存里，用于按来源限额（10 分钟窗口），随房间一起清除。The source of each post (its IP address, or the paying address for a paid post) is held in memory with the room, for the per-source limit (10-minute window), and cleared with the room.
  • 新建房间的计数按 IP，放在 Worker 实例的内存里，每分钟一个窗口。日志只有错误信息。New-room counters are keyed by IP address and held in the Worker instance's memory, per minute. The logs hold error messages only.

日志存在哪里、留多久Where the logs are kept, and for how long

  • 以上日志行存在 Cloudflare 的 Workers Logs 里，按套餐保留（免费版 3 天、付费版 7 天；我们用的是哪一档：待核实）。The log lines above are kept in Cloudflare's Workers Logs for the plan's retention (3 days on the free plan, 7 on the paid plan; which plan we are on: to be verified).
  • 两个 Worker 的配置已关闭 Cloudflare 的逐请求调用日志（invocation logs）与追踪（traces），并隐去网址里的查询串。Both Workers' configuration turns off Cloudflare's per-request invocation logs and traces, and redacts query strings from URLs.

我们不记什么What we do not record

  • api.tapeapi.fun 的日志不写请求参数、回答内容，也不写 IP 本身；签名的回答发出后不另存。api.tapeapi.fun writes neither request params nor answers nor the IP address itself into its logs; a signed answer is not stored once sent.
  • 中继不解密帧，也不把帧写进持久存储。The relay does not decrypt frames and does not write them to persistent storage.
  • 核验页的回执放在网址的 #r= 片段里，浏览器不会把片段发给任何服务器；核验在你的浏览器里完成。On the verification page the receipt rides in the #r= fragment of the URL, which browsers never send to a server; the check runs in your browser.
  • 网站没有第三方统计或广告脚本。浏览器本地存储（localStorage）里只放：语言与主题；"我的服务"页上你添加的服务列表；持有人操作台里填写中的服务设置与 ChannelBus 部署记录。这些只在你自己的浏览器里。The website runs no third-party analytics or advertising scripts. Browser storage (localStorage) holds only: the language and theme; the list of services you add on the Dashboard; the service settings you are filling in and the ChannelBus deployment record in the holder console. These stay in your own browser.
  • 我们不运行 AI 签名旁路（每个服务方运行自己的），所以看不到任何服务方的提示词、回答或 API 密钥。We run no AI signing sidecar (each service provider runs its own), so we see no provider's prompts, answers or API keys.

别人看得到什么What others see

  • Cloudflare：三样东西都跑在 Cloudflare 上（网站在 Cloudflare Pages，另外两个在 Workers），它看得到每个请求的 IP、时间与网址。Cloudflare 自己对请求的记录是否含客户端 IP：待核实。Cloudflare Pages 是否为网站保留访问日志、保留多久：待核实。Cloudflare: all three run on Cloudflare (the website on Cloudflare Pages, the other two on Workers), and it sees each request's IP address, time and URL. Whether Cloudflare's own records of a request include the client IP address: to be verified. Whether Cloudflare Pages keeps access logs for the website, and for how long: to be verified.
  • 服务方：你调用的第三方服务看得到请求内容、IP 与 API 密钥，付费调用时还有你的钱包地址。它们的日志由它们自己决定，本页无法代表它们。Service providers: a third-party service you call sees the content of your requests, your IP address and your API key, and your wallet address on paid calls. Their logs are their own; this page cannot speak for them.
  • 公共 RPC 节点：网站、调试台、核验页和 SDK 读链时直连公共节点（BNB Chain 默认是 bsc-dataseed.bnbchain.org、bsc-mainnet.public.blastapi.io、rpc-bsc.48.club；X Layer 与 Base 各有自己的默认节点）。节点运营方看得到你的 IP 和你在查哪个服务。为了防止单个节点给出错误数据，SDK 默认同时询问两到三家；你可以换成自己的节点。Public RPC nodes: the website, the playground, the verification page and the SDK read the chain from public nodes directly (on BNB Chain by default bsc-dataseed.bnbchain.org, bsc-mainnet.public.blastapi.io and rpc-bsc.48.club; X Layer and Base have their own defaults). Their operators see your IP address and which service you are looking up. So that no single node can feed wrong data, the SDK asks two or three of them by default; you can use your own node instead.
  • 链上：TapeOut 身份、服务清单、委托、ChannelBus 上的帖子和付款记录，写上去就永久公开。On chain: TapeOut identities, service manifests, delegations, ChannelBus posts and payment records are public for good once written.

回执与链接Receipts and links

  • AI 用量回执只带请求与回答的哈希；SDK 与 tapeapi-verify 默认给请求加一段随机空白，短提示词因此无法从哈希猜出。AI usage receipts carry hashes of the request and the answer; the SDK and tapeapi-verify add random whitespace to each request by default, so a short prompt cannot be guessed from its hash.
  • MCP 核验链接默认只带哈希；显式开启的带原文链接里含对话内容。取自小集合的参数（地址、token id、交易对）仍可能从哈希猜出。MCP verify links carry hashes by default; a link with content, which must be asked for, contains the conversation. Params from a small set (an address, a token id, a price pair) can still be guessed from their hash.
  • 回执不证明实际跑的是哪个模型：它证明谁的密钥签了什么、在什么时间。A receipt does not prove which model actually ran: it proves whose key signed what, and when.
