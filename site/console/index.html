在手机钱包的内置浏览器里打开本页。本页只会请求你的钱包确认签名和交易，从不索要私钥或助记词。它帮 TapeOut 电路的持有人把自己的容器发布成一个 TapeAPI 服务：读电路、生成服务密钥、签委托、把清单写上链。 Open this page in your wallet's in-app browser. It only asks your wallet to confirm signatures and transactions; it never asks for a key or a seed phrase. It helps the holder of a TapeOut circuit publish their container as a TapeAPI service: read the circuit, generate a service key, sign the delegation, publish the manifest on chain.

1. 连接钱包1. Connect your wallet

X Layer 与 Base 上的名字带区号：1.2.344.tape 是 X Layer（区号 2）上 344 号处理器的电路 1，Base 的区号是 3。在这两条链上，本页只发布身份与清单（免费方法）；委托按这条链签名，只在这条链上有效。付费与 ChannelBus 只在 BNB Chain。 Names on X Layer and Base carry an area code: 1.2.344.tape is circuit 1 of processor 344 on X Layer (area 2); Base is area 3. On these chains this page publishes identity and the manifest only (free methods); the delegation is signed for this chain and is valid on it alone. Payments and ChannelBus stay on BNB Chain.

2. 你的电路2. Your circuit

两个框都填数字，不是地址。电路名字 <电路>.<处理器>.tape：例如 11.1013.tape，左边填处理器 1013，右边填电路 11（顺序和名字里相反）。页面从链上读出容器地址，并确认你连接的钱包就是当前持有人。 Both boxes take numbers, not addresses. A circuit is named <circuit>.<processor>.tape: for 11.1013.tape, enter processor 1013 on the left and circuit 11 on the right (the reverse of the name). The page reads the container address from the chain and checks that the connected wallet is the current holder.

3. 服务密钥与变量3. Service key and variables

服务用这把密钥给每个回答签名。它在你的手机上生成，本页不会把它发到任何地方，也不会保存；关掉页面就没了。复制后粘到 Cloudflare： Workers 和 Pages → 你的服务的 Worker（例如 my-tapeapi-service；本项目自己的是 tapeapi-provider 和 tapeapi-relay）→ 设置 → “+ 添加变量”，名称 SIGNER_KEY，“密钥”方框打勾。先刷新 Cloudflare 页面再改，旧页面保存时会覆盖别的变量。 The service signs every answer with this key. It is generated on your phone; this page never sends it anywhere and does not keep it, so it is gone when you close the page. Copy it into Cloudflare: Workers & Pages → your Worker (for example my-tapeapi-service; the project's own are tapeapi-provider and tapeapi-relay) → Settings → "+ Add variable", name SIGNER_KEY, with Encrypt / Secret ticked. Reload the Cloudflare page before editing: saving from a stale page overwrites the other variables.

4. 签委托4. Sign the delegation

设好 SIGNER_KEY 和上面的变量、服务重新部署后，本页从服务读出它的签名地址，你用钱包签一个委托（EIP-712，只授权这把服务密钥代表你的容器回答，不涉及任何资金，90 天后到期）。 Once SIGNER_KEY and the variables above are set and the service has redeployed, this page reads the service's signing address and you sign a delegation with your wallet (EIP-712: it only lets this service key answer for your container, moves no funds, and expires in 90 days).

续期（委托快到期或已到期，服务和密钥都不变）：不用第 3 步。本页为第 2 步在链上清单里读到的签名地址重签委托。这样是安全的：链上那份委托是你自己签给这个地址的，本页先核对它确实恢复出你（当前持有人）、服务报出的也正是这个地址，才请你签名；新委托只延长期限，不授权任何新密钥。服务网址必须与链上的一致。如果你怀疑服务密钥泄露了，不要续期，改用第 3 步生成新密钥。 Renewal (the delegation is about to expire or has expired; same service, same key): skip step 3. This page re-signs the delegation for the signing address read from the manifest on chain in step 2. This is safe: the delegation on chain is one you signed for that address, and the page checks that it recovers to you, the current holder, and that the service reports exactly that address, before asking you to sign; the new delegation only extends the term and authorises no new key. The service URL must be the one on chain. If you think the service key has leaked, do not renew: generate a new key in step 3.

5. 把清单写上链5. Publish the manifest

把第 4 步的两个值设为变量、服务重新部署后，本页读取服务提供的清单，逐项核对它与你签的一致，再发一笔 SiteRegistry.putFile 交易把它写进容器站点。 Once the two values from step 4 are set as variables and the service has redeployed, this page reads the manifest the service serves, checks every field against what you signed, then sends one SiteRegistry.putFile transaction that writes it into your container's site.

如果服务是某个 MCP 服务器的签名代理（清单里有 mcp 字段），本页还会自己去读它的工具列表、计算工具定义的摘要，与服务报出的一致才发布，并在钱包请求之前列出每个工具的名字和说明。 If the service is the signing proxy of an MCP server (its manifest has an mcp field), this page also reads its tool list itself, hashes the tool definitions, publishes only if that matches what the service reports, and lists every tool's name and description before your wallet is asked.

AI 服务的价目表（清单里有 ai 字段，例如 new-api 旁路）：发布时本页按 TAP-20 §3.9 核对它，并在钱包请求之前把每种接口格式的地址和每个模型的价格列成表。你也可以先在这里粘贴或上传价目表预览：models.json（只有模型，本页按第 4 步的服务网址补上四种格式的地址，与旁路的做法相同）、ai 字段本身，或整份清单。预览过的价目表必须与服务提供的一字不差才会发布。第 4 步的委托不覆盖价目表，写上链的那笔交易才覆盖。 An AI service's price table (the manifest has an ai field, as the new-api sidecar's does): when publishing, this page checks it against TAP-20 §3.9 and, before your wallet is asked, lists every API format's address and every model's prices in a table. You can also paste or upload the table here first to preview it: a models.json (models only; the page adds the four formats' addresses on the service URL of step 4, as the sidecar does), the ai field itself, or a whole manifest. A previewed table is published only if the service serves exactly the same one. The delegation of step 4 does not cover the price table; the transaction that writes it on chain does.

价格只是公示：TapeAPI 不结算这些价格，你的用户照旧向你付费；回执里的金额是任何人都能重算的声明，不是付款。按规范，BNB、USDT、USDC、ETH、USD1 指 BNB Chain 上的代币，USD 只作展示。 Prices are published, not settled: TapeAPI settles none of them and your users pay you as they do today; the amount in a receipt is a claim anyone can recompute, not a payment. Under the spec, BNB, USDT, USDC, ETH and USD1 name the tokens on BNB Chain, and USD is for display only.

你选的是 X Layer 或 Base：这两条链上 TapeAPI 的支付暂不开放，价目表只作公示，任何人都不能在这条链上按它付费。 You chose X Layer or Base: TapeAPI payments are not open on these chains yet, so the price table is published for display only and nobody can pay by it on this chain.

核对某个地址上的代码是否与测试过的构建逐字节一致，以及两个常量。部署后会自动核对；也可以输入地址手动核对。 Checks that the code at an address equals the tested build byte for byte, and the two constants. It runs by itself after a deployment; you can also enter an address.

页面源码：site/console。部署的字节来自 channelbus.json，合约测试 ConsoleBytecode.t.sol 保证它与测试过的合约完全一致。 Page source: site/console. The deployed bytes come from channelbus.json; the contract test ConsoleBytecode.t.sol keeps them identical to the tested contract.
