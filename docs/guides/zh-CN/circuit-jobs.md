# Circuit Jobs（草案；TapeAPI 不提供代码）

Circuit Jobs（电路作业）是一份 TAP 草案：TapeOutProtocol/TAPs pull request #85（头提交 `d1b19ae`；构想 issue #82；已提交，目前转为 draft PR）。它让一个
agent 付钱请另一个 agent 跑一个电路，付款由链上的争议博弈来结算，而不是由某个人来判定。草案自称有条件（conditional）。
**TapeAPI 不为它提供任何代码**：没有包、没有命令、没有合约。本页说明这份草案是什么、为什么没有东西可装，以及它和 TapeAPI 已提供的部分是什么关系。
本页只是文档，不替草案做任何决定。

## 草案描述的是什么

- **作业。** BNB 智能链上已部署的 Agentic Commerce 内核（ERC-8183）里一个有托管的作业：委托方存入预算，提供方提交交付物，创建时固定的
  一个评估者账户完成作业（向提供方付款）或拒绝作业（退款给委托方）。草案写明它是为了与这个已部署的内核互通而写的，不是 ERC-8183 的官方扩展。
- **评估者。** 一个合约 `TapCircuitEvaluator`，同时是作业的评估者和钩子，没有自由裁量权、不托管资金、没有所有者。任务是一个 `tapnet/2`
  网表的确定性运行，在作业存入预算之前固定为作业规格。交付物是另一份审阅中草案《Large Netlists and Verifiable Execution》（pull request #74）
  的可验证执行博弈里的主张 id（`bytes32(claimId)`）。博弈报告主张被接受时，评估者完成作业；报告被拒绝时，拒绝作业；其余情况什么都不做。
  十条规则（J-1 至 J-10）涵盖存入预算前的绑定、到期与挑战窗口、gas、重入，以及钉住的内核。
- **范围。** 只限确定性运行。生成文本、检索、人的判断以及任何"质量"概念都不在范围内。在任何现实的博弈参数下，结算都以天计，所以它面向
  会被第三方读取的批量结果，不面向交互式调用。

## 为什么 TapeAPI 不为它提供代码

下面每一条都出自草案自己的文字或其资产的记录：

- **Solidity 参考实现不是部署。** 在 `d1b19ae`，草案的资产里除了 Python 模型和向量，还有一份 Solidity 参考实现（一个 Foundry 项目，含评估者合约，
  在本地分叉上对着已部署的内核运行）。草案写明它**未经审计、未部署**，测试里用的是一个替身博弈（`MockGame`），#74 那个博弈的适配器还没有写。
  TapeAPI 不运行它、不随包提供它，也不为它担保。
- **没有任何部署。** 草案的 Deployments 一节写明：本草案下没有任何部署，任何链上都没有。它读取的博弈在 #74 里规定，而 #74 本身也是
  一份已提交（评审中）的草案，也没有列出这种博弈的任何部署。草案里还有一个前提没有落定（Pre-1：博弈的 `maxSettlementSeconds` 是否真的是上限）。
- **内核可以升级。** 草案依赖的事实是在区块 129,352,831 的本地分叉上测得的，当时未落定的几项又在 2026-10-29 于区块 130,339,400 重新测量过（M-5），只对这两个区块的实现成立；内核的代理可以由它的所有者升级
  （读取时是一个 2-of-3 Safe）。草案规定：在这些事实重新测量并记录之前，任何实现都不得被说成符合草案，并要求工具把更早部署的评估者
  显示为"未核验"。TapeAPI 若做一个作业规格工具，将没有任何可以对照的部署，而且会被读成对某一个内核实现的表态。
- **没有需求证据。** 这批 agent 草案的作者在其总览的已知限制里列出：电路作业目前没有需求证据。

草案现在有了固定提交的 Solidity 参考实现和有记录的重新测量，但两者针对的都是一个替身博弈和一个本地分叉。如果其余情况变了（#74 合并、对在用的实现再测一次部署、并且有人需要），TapeAPI 可以再看。本页不作任何承诺。

## 和 TapeAPI 已提供部分的关系

- **回执。** TapeAPI 回执（TAPI-21 §3.5）是服务对请求字节与回答字节的签名声明。电路作业的交付物是博弈里的主张 id，不是 TapeAPI 回执，
  评估者只读博弈的状态。回执的哈希和任何其它引用一样放得进内核的 `bytes32` 字段，但 TapeAPI 里没有任何东西往那里写。见
  [回执与支付协议](receipts-and-payment-protocols.md)第 5 节。
- **Agent 护照。** [Agent 护照](passport.md)只读地核对一个 ERC-8004 身份与一枚 TapeOut 电路是否属于同一个持有人。Circuit Jobs 不写任何
  身份、声誉或验证登记表，也不读护照；一个把电路当作服务提供的 agent 可以两者都有，彼此独立。
- **策略电路。** [策略电路](policy-circuit.md)在链下重跑一条 `tapnet/1` 支出规则，由想核查的一方自己核查；电路作业则经由博弈在链上结算一次
  `tapnet/2` 运行。两者都用 TapeOut 电路，用途不同。策略绑定的主体种类里没有一种指向 ERC-8183 作业。
- **资金。** 这里 TapeAPI 不托管任何人的预算，也不替任何人发送交易。TapeAPI 自己的付费调用依赖的托管是另一个合约，至今仍未经审计、未部署。
