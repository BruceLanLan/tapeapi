# 费用模型 v0.2：零协议费 + 开发者自愿贡献

## 原则
1. **标准层永远免费。** 解析身份、读清单、验签、发现服务，不收费、不经过任何我们的服务器。
2. **协议不抽成。** Escrow 没有运营方费率开关。与 DeWEB、TapeSend 的零协议费先例一致。
3. **贡献由服务提供者自己决定。** 每个提供者可以为自己的服务设置一个 `contributionBps`（万分比），默认 0。结算时按该比例从提供者应得的部分划给"标准维护金库"。
4. **建议值写在规范里，不写在合约里。** TAP-22 建议 100 bps（1%），并说明用途：规范维护、参考实现、审计、目录站运营。合约只设硬上限 5000 bps 防误操作。
5. **贡献可见。** 目录站显示每个服务的贡献比例；SDK 暴露该字段。目录或钱包可据此展示（例如"Supporter"标识，目前尚无实现），不给的人功能完全一样。

## 为什么这样收比"平台抽成"好
- **符合生态文化。** 创始人零协议费已经成为社区默契，反其道而行会直接失去协议级资格。
- **与 Web2 企业的预期一致。** 企业接入时最怕的是平台费率单方面变化。这里费率由自己设，改动自己发交易。
- **激励是正向的。** 贡献比例公开，目录排序可以把"贡献 + 可用率 + 结算量"综合计入，让愿意支持标准的服务得到更多曝光，而不是惩罚不给的人。
- **金库地址可治理。** 初期是我们的多签，未来可以移交给 TapeOut 官方金库或社区多签，合约里只是一个可换的地址，换地址必须发事件。

## 具体规则（进合约）
- `setContribution(circuits, tokenId, bps)`：调用者必须是该电路当前持有人；provider = hub.accountOf(circuits, tokenId)；bps ≤ 5000。
- `settle()`：`delta` 先算出，`contribution = delta * bps / 10000` 给 `treasury`，余下给 provider。bps 为 0 时不产生任何转账。
- `treasury` 由 owner 设置，改动发 `TreasuryChanged`。owner 无其它权力，无法改任何人的 bps，无法暂停，无法提取用户资金。
- 别名登记：`ServiceDirectory` 可选要求 `DomainBinding.isContainerLive(container)` 为真。激活费 0.08 BNB/30 天付给协议，不付给我们。`labelFee` 保留为参数，默认 0。

## 我们的收入从哪来（不变）
自营服务按次收 BEM、托管控制台、帮企业铸电路开容器写清单的一站式服务。见 BUSINESS.md。手续费不再是收入线，贡献金库是维护费，公开报账。

## 可以作为"开关"的部分
`contributionBps` 就是开关，只是开关在提供者手里而不是我们手里。若未来社区希望有统一协议费，正确的路径是新的 TAP 加新的 Escrow 部署，而不是给现有合约加后门。
