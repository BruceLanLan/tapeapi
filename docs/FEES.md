# 费用模型 v0.3：无强制协议费 + 默认 1% 维护贡献（提供者可关闭）

> 2026-09-28 起取代 v0.2（"零协议费，贡献默认 0，建议 1%"）。变化在于贡献的**默认值**从 0 改为 1%，
> 并写成合约常量；运营方依然没有费率开关，消费者的价格依然不变。规范见 TAPI-22 §3.4。
> 2026-10-05（仍在任何部署之前）：上限从 50% 降到 **20%**；目录站不按贡献比例排序、不据此打标记；
> 合约区分"从未设定"（适用默认 1%）与"设为 0"。

**今天没有任何调用收费。** 付费调用用的托管合约还没有部署，要先通过独立审计才会部署。在那之前，所有线上方法都免费，
下面说的贡献一分钱也没有收过。

## 原则
1. **标准层永远免费。** 解析身份、读清单、验签、发现服务，不收费、不经过任何我们的服务器。
2. **没有强制协议费。** 托管合约没有运营方的费率开关，也不能暂停。协议本身不向消费者收取任何费用。
3. **默认 1% 维护贡献，提供者可以改成 0。** 付费调用通过 TapeAPI 托管合约结算时，默认从提供者应得的部分划出 1%
   给维护金库。消费者付的价格不变。每个提供者都可以为自己的服务把比例改成 0（关闭），或 0 到 20% 之间的任意值。
4. **默认值是合约常量，不是 owner 参数。** `DEFAULT_CONTRIBUTION_BPS = 100` 写死在合约里，部署后谁都改不了；
   上限 `MAX_CONTRIBUTION_BPS = 2000`（20%）同样是常量。owner 唯一的权力是更换金库（treasury）地址（以及两步转移 owner 本身）。
5. **关掉不受惩罚。** 比例为 0 的服务在合约、SDK、其他提供者那里得到完全相同的对待。目录站可以显示比例，
   但不能因此限制功能，也**不能按比例给服务排序或打任何标记**（TAPI-22 §3.4 的 MUST NOT）。否则贡献就成了花钱买排名，
   "关掉不受惩罚"也就名存实亡。我们自己的目录站（`site/directory`）只按固定顺序列出，不排名。
6. **贡献可见。** SDK 在解析服务时读出该服务的比例（`svc.contribution`），目录站也可以展示。

## 为什么默认开启是诚实的
- **改在任何人付费之前。** 托管合约没有部署，没有人付过一分钱，也没有人因为"默认 0"而接入后被改了规则。
  这是上线前的规则更新，不是事后加费。
- **消费者不受影响。** 贡献从提供者的所得里划出，消费者的价格一分不变。
- **提供者一笔交易就能关掉。** 电路持有人调用 `setContribution(circuits, tokenId, 0)` 即可，不需要任何人批准。
- **运营方拿不到开关。** 默认值是常量，owner 不能调高、不能改任何人的比例、不能暂停、不能动余额。
  如果将来想改默认值，只能部署一个新合约，旧合约照常运行。
- **为什么不是默认 0。** 规范维护、参考实现、审计、目录站运营需要一个稳定来源。默认 0 实际上等于没有来源；
  默认 1% 加上随时可关，是对维护者和提供者都说得清的折中。

## 具体规则（进合约）
- `setContribution(circuits, tokenId, bps)`：调用者必须是该电路当前持有人；provider = hub.accountOf(circuits, tokenId)；
  0 ≤ bps ≤ 2000。设过之后（包括设为 0），该值取代默认值。合约单独记录"是否设过"，所以设为 0 读到的就是 0，
  不会退回默认值。
- `contributionOf(provider)`：没设过时返回 100，设过则返回所设的值。
- `settle()`：先算出本次实付 `paid`（`min(delta, 通道余额)`），按结算这一刻的比例算 `contribution = paid * bps / 10000`
  （向下取整），记入金库应收额 `treasuryAccrued`，余下 `paid - contribution` 转给 provider；`settle` 只做这一笔转账，
  从不向 `treasury` 转账，所以收不了款的金库挡不住任何结算。`Settled` 事件带上所用的 `bps`，链下可直接核对。
  bps 为 0 或金额向下取整为 0 时不记入任何应收。
- `claimTreasury()`：任何人可调，把全部 `treasuryAccrued` 付给当前 `treasury`（收款人固定，调用者只决定时机），
  发 `TreasuryClaimed`；没有应收时回滚。
- 改比例立即生效、不追溯：已结算的不重算，尚未结算的凭证按结算时的比例拆分。
- `treasury` 由 owner 设置，改动发 `TreasuryChanged`；不能设成零地址、托管合约自身或代币合约。"金库"这个角色包括已记账
  未领取的应收额：换金库时合约先把这笔钱付给**旧**金库，所以 owner 改不走旧金库已经挣到的钱；只有旧金库收不了款
  （例如被冻结）时，这笔应收才留给新金库领取。除此之外 owner 没有其它权力。
- 别名登记：`ServiceDirectory` 可选要求 `DomainBinding.isContainerLive(container)` 为真。激活费 0.08 BNB/30 天付给协议，
  不付给我们。`labelFee` 保留为参数，默认 0。

**实现状态：** 2026-10-05 起，仓库里的托管合约（`contracts/src/TapeAPIEscrow.sol`，v3 送审候选）已按本版实现默认值 1%、
上限 20%、"从未设定 / 设为 0"的区分和上面的拉取式金库（TAPI-22 §3.3、§3.4 已同步规定）。它仍未经审计、未部署；
只有送审通过的那一版会部署。

## 金库
初期金库地址就是部署合约的钱包，部署时公开；换地址必须发 `TreasuryChanged` 事件，且合约先把旧金库未领取的应收付给旧金库。

## 结算代币与价格（计划中，下一版托管）
计划送审的那一版托管，一个实例只托管一种 ERC-20（同一份字节码，代币是不可变的构造参数）。**首个支持的实例是
BNB Smart Chain 上的 USDT 锚定币**（Binance-Peg "BSC-USD"，`0x55d398326f99059fF775485246999027B3197955`；它由 Binance 发行，
不是 Tether，所以展示时写 "USDT (Binance-Peg)" 并附地址）。BEM、WBNB（以及经 WBNB 的 BNB）按需，用同一份字节码，不是首发。

一种代币要被准入，必须逐项满足：合约不可升级；没有冻结、暂停、拉黑或销毁他人余额的函数（或这些函数任何人都不可达）；转账是标准
ERC-20 行为（不扣费、不变基、无收款方钩子）；`decimals` 固定，由代币合约自己的 `decimals()` 读取，且在 8 到 18 之间；源码已验证，
增发、升级、暂停、冻结的权限表公开。USDT 锚定币的逐项依据见 TAPI-22 §3.5。不合格的有：USDC（Binance-Peg，透明代理，管理员是单个
外部账户，可即时升级）、USD1 与 FDUSD（可升级、可冻结、可暂停）、X Layer 上的 USD₮0（6 位小数，有黑名单与销毁）。增发权与发行方背书
是价值风险而不是锁死风险：按实例披露，不决定准入。

**价格模板。** 默认以 USDT 计价。托管金额一律按代币合约自己的 `decimals()` 读取（USDT 锚定币是 18 位：10 USDT 是 10 × 10¹⁸ 个最小单位），
不要把 BEM 的 8 位小数套到托管金额上；清单里的 `priceBEM` 保持不变（兼容）。多币种的 `prices` 映射尚未规定。SDK 默认只为已审计名单内的
托管构造 `approve` 与 `fund` 交易（建议，实验性）。

**原生 BNB** 不是托管币：托管只收 ERC-20，BNB 由付款方先包成 WBNB。服务容器只在发送方给足 gas 时才能收下原生 BNB，且收到 WBNB 后自己
无法拆包（WBNB 的 `withdraw` 只给 2,300 gas），所以原生 BNB 只是直接充值到容器的一条路径。

合约侧（每个实例一种不可变代币、不读小数位）已在仓库中实现，但没有部署，也没有审计；TAPI-22 §3.1–§3.4 适用于每个实例，
§3.5 是说明性内容。多币种价格与 BEM 以外代币的 `data.price` 形式仍未规定。

## 我们的收入从哪来（不变）
自营服务按次收 BEM、托管控制台、帮企业铸电路开容器写清单的一站式服务。见 BUSINESS.md。维护贡献进金库，用于维护，公开报账。
TapeAPI 的点子来自 @Theairresearch，自 2026-10-05 起 TapeAPI 收入扣除第三方现金成本后的 10% 永久归其所有（口径见 BUSINESS.md 的分成承诺）。

## 可以作为"开关"的部分
比例就是开关，开关在每个提供者手里，不在我们手里。若将来社区希望有统一的协议费，正确路径是新的 TAP 加新的托管部署，
而不是给现有合约加后门。本次默认值的调整也走这条路径：它随下一版托管一起部署、一起审计。
